# 経歴カードのスクロール表示

## 構造

カードごとに `.history-stage` を設け、その内部でカード全体をstickyにする。
フェードと現在地の切り替えは既存のGSAP ScrollTriggerで管理し、サイズ変更時に境界を再計算する。標準スクロールの位置補正とSPのクリッピングもScrollTriggerの更新に同期する。
重なり幅には各カードの実際の高さを使い、次のカードが同じ上端まで到達してから、親の終端に沿って前のカード全体が画面外へ流れる。
固定できるカードは高さを揃え、次のカードから前のカードの下端がはみ出さないようにする。
本文・画像・背景は一緒に移動し、縮小・複製はしない。
次のカードが75%重なるまでは不透明に保ち、残り25%の重なりに応じて前のカード全体のopacityを1から0へ連続的に変える。完全に覆われた後は0を維持し、逆方向に戻ると同じ割合で再表示する。読み上げ対象やスクロール先として残すため、aria-hidden・inert・display: noneは使用しない。
固定による現在の位置ずれとカード内の要素位置をscroll-margin-topへ反映し、標準スクロールの移動先を補正する。VoiceOverの検出やフォーカスの強制移動は行わない。
画面高に収まらないカードは固定せず、全文を通常スクロールで読めるようにする。
SPではナビ下端より上へ通過したカードをclip-pathで切り取り、ナビ上側への再露出を防ぐ。
現在地ナビはstickyを維持する。停止操作・動きを減らす設定ではカードを通常の縦並びにする。

Chrome + VoiceOverのローターによるスクロール追従は、カード全体の重なりと完全に覆われた後の透明化を実装した段階で、ユーザーによる動作確認済み。その後のSPクリッピング・フェード開始位置・余白の調整は自動確認済みで、最終差分の実機確認は下記の手順で行う。

## Chrome + VoiceOverでの受け入れ確認手順

1. アニメーションを有効にし、ページ末尾までスクロールしてからVoiceOverを起動する。
2. ローターの見出しから「名古屋大学入学」へ移動する。見出しがナビに隠れず、画面にも表示されること。
3. 文章・画像へ順に移動し、読み上げ対象が画面にも表示されること。
4. 他の経歴にも順方向・逆方向で移動し、透明な本文や背面に隠れる本文がないこと。
5. 現在地ナビから各経歴へ移動できること。
6. アニメーション停止時、および狭い画面幅でも同じ操作を確認する。

ブラウザ・macOSのバージョンと、使用したVoiceOver操作を結果とともに記録する。

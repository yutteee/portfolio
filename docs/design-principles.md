# デザイン原則

このポートフォリオのデザインシステムの土台となる原則。個々のトークンやコンポーネントの「なぜ」をここで規定する。新しい画面・コンポーネント・装飾を作るとき、迷ったら各項目の「判断基準」に立ち返ること。

実装レベルのルール（トークンの使い方・コンポーネントパターン）は `docs/design-system.md` を参照。

## コンセプト — テックを抽象で語る

エンジニアのサイトだが、ターミナル風・コード風・サイバー風の意匠は使わない。

このサイトの中心にあるのは、丸みのあるフラットな図形へ抽象化された PC のイラスト。写実的なガジェットではなく、角丸の四角形（モニター）と台形（キーボード）だけで描かれる。これは「テックが好き」ではなく「**画面に現れる UI が好き**」であることの表明。

しかもこの PC は画像ですらなく、`border-radius`・`border`・塗りという **UI の構成要素そのもの**で描かれている。モチーフ（画面）と手段（UI プリミティブ）が一致していることが、このサイトのアイデンティティの核。

### PC モチーフの現れ方

- **favicon**: スカイブルー地にモニターとキーボードの図形
- **トップのヒーロー**: CSS 図形だけで描いた PC。スクロールするとモニターが広がり、画面がサイトそのものになる
- **About セクション**: モニターの中に顔写真を表示し、画面の中に自分を置く

### 判断基準

- イラストや装飾を足すとき: 写実・具象ではなく、角丸＋フラットな塗りの図形で描けるかをまず考える
- 「エンジニアらしさ」を出したくなったとき: コードやターミナルの見た目ではなく、画面・UI のメタファーで表現する
- 新しいモチーフを増やす前に、まず PC（モニター）モチーフの応用でできないか検討する

## 原則

### 1. シンプルに、一点だけ大胆に

シンプルなレイアウトを基調に、1 画面につきひとつだけ大胆な要素（特大タイポグラフィ、面の塗りつぶし、あえての右寄せ）を置く。

- **Why**: シンプルさは好みであると同時にアクセシビリティの担保でもある。大胆さを一点に絞ることで、シンプルさを壊さずに個性を出せる。
- **現れ方**: hero の `--step-6` の特大タイポ、アクセント色（`--color-accent`）の面塗り、ページタイトルの右寄せ、プロダクト一覧の変則的な並び
- **判断基準**: 大胆な要素が 1 画面に 2 つ以上競合していたら、どちらかを引く。逆に「無難すぎる」と感じたら、タイポ・塗り・配置のどれか一点だけを崩す

### 2. アクセシビリティは装飾より先

WCAG 2.1 レベル AA 準拠は成果ではなく前提。実装後ではなく、デザインの段階でコントラスト・ズーム耐性・フォーカスを考える。

- **Why**: 実装してからアクセシビリティを直すのは高くつく。シンプルなレイアウトを選ぶ理由の半分はここにある
- **現れ方**: セマンティックカラートークンによるライト / ダーク両対応、画像の具体的な代替テキスト、表示切り替え時のフォーカス管理（AnimationIcon のボタンなど）
- **判断基準**: 大胆さとアクセシビリティが衝突したら、アクセシビリティが勝つ。コントラスト比を満たせないアクセントの使い方はしない

### 3. 動きは気持ちよく、止められるように

アニメーションは「気持ちよさ」のために入れる。ただし、すべての動きはユーザーが止められる。

- **Why**: スクロール連動アニメーションは、人によってはめまいや集中の阻害を引き起こす。楽しさと安全は両立させる
- **現れ方**: GSAP のスクロールアニメーション、画面右下の停止 / 再生ボタン、`html.stop` クラスによる一括停止と `localStorage` での永続化
- **判断基準**: 新しいアニメーションを足すときは `html.stop` で止まることを必ず確認する。止める手段を用意できない動きは実装しない

# 実装ガイド

このポートフォリオは Astro + React で構成されています。UI コンポーネントは専用の Context / Provider を必要としません。

## スタイルとテーマ

Storybook は `.storybook/preview.ts` から `destyle.css` と `src/styles/global.css` を読み込みます。ブランドフォント **BIZ UDPGothic** は `.storybook/preview-head.html` で読み込みます。ネットワークにつながらない環境では代替フォントになります。

ライトが既定で、`html.dark` によってダークモードへ切り替わります。色は `--color-text` などのセマンティックトークンを使います。コンポーネントにダーク専用の色定義は不要です。トークンページの Light / Dark で両方を確認できます。

## トークンの使い方

- 色・余白・角丸・文字サイズ・gap・影・padding・margin・枠線色は `var(--...)` を使います。CSS のチェックで強制されます。
- プリミティブ色の直接参照は、1〜2 箇所しか使わない例外的なケースに限ります。
- 本文は `--step-0`、hero のページ見出しは `--step-6`、本文の行長は `--text-max-width` が基準です。
- `--space-s-m` などのペアは画面幅に応じて余白が開閉します。セクション間などの可変余白に使います。
- `--bp-*` は値の管理用です。メディアクエリに CSS 変数は使わず、リテラル値と `/* sync with --bp-md */` などのコメントを併記します。
- すべての実値は `src/styles/global.css` が正本です。Storybook のトークン一覧はこのファイルから読み込みます。

## 余白の設計

**余白は要素同士の関係から選びます。関連する情報は近く、話題が変わるところは広く取ります。** このサイトでは、特に大きな話題の切り替わりに大胆な余白を使います。

### 用途から選ぶ

最初に関係を分類し、次の値を出発点にします。同じ関係の要素には同じ間隔を使い、情報の長さや配置に合わせて実画面で調整します。

数値は `1rem = 16px`、画面幅 320px → 1440px での概算です。固定値を直接指定せず、既存のトークンを使います。

| 関係・用途 | 例 | トークン・式 | 余白の目安 |
| --- | --- | --- | --- |
| 一つの情報の中 | 日付と種別、補足情報 | `--space-2xs` / `--space-s` | 8→10px / 16→20px |
| 同じ話題を構成する | 自己紹介の名前・説明・関連ボタン | `--space-m` | 24→30px |
| 見出しと内容のまとまり | トップのセクション見出し行と一覧 | `--space-l-xl` | 32→60px |
| 同列の項目 | 縦に並ぶ作品・記事・スクラップ、一覧の行間 | `--space-2xl` | 64→80px |
| 横並びの項目 | 作品・記事一覧の列間 | `--space-xl` | 48→60px |
| 詳細ページ内の大きなまとまり | タイトル・画像の領域と本文、縦並びの目次と本文 | `--space-2xl` | 64→80px |
| 大きな話題の切り替わり | トップのセクション間、本文とコメント欄 | `calc(var(--space-3xl) + var(--space-xl))` | 144→180px |
| 内容の終わり | 一覧・詳細ページの下側の内余白 | 同上 | 144→180px |

表は用途ごとの選択基準であり、すべてのページへ同じ数値を強制するものではありません。たとえばサイトマップはリンクの階層を読み取るページなので、大分類間は `--space-l-xl`、子リンク間は `--space-s` とし、各リンクを独立した大きなセクションとして扱いません。

### 大胆に広げる場所と、近づける場所

- 大きく広げるのは、自己紹介から作品へ移るときなど、読む目的や話題が切り替わる場所です。
- 見出しは、それが説明する内容に近づけます。見出しの前と後を同じ大きさにして、どちらの内容に属するか曖昧にしません。
- 作品の画像・名前・説明、記事の見出し・日付など、一つの項目の内部はまとまりを保ちます。一覧の間隔を広げても、内部を同じ倍率で広げる必要はありません。
- PC モチーフの部品間隔やスクロール演出に必要な距離は、情報を区切る余白とは別の目的です。表の数値へ一律に置き換えません。

### 長文の章・節・段落

記事・作品詳細の本文は、段落を読み続ける間隔と章の切り替わりを分けます。`.main-wrapper` の基本の `gap` は `--space-s`。見出しの前に次の余白を加えます。

| 見出し | 前側の追加余白 | 基本の gap を含む要素間隔 |
| --- | --- | --- |
| h2：章 | `--space-2xl`（64→80px） | 80→100px |
| h3：節 | `--space-l`（32→40px） | 48→60px |
| h4：小さな区切り | `--space-m`（24→30px） | 40→50px |

これは本文の直接の子要素として配置された見出しの目安です。本文の先頭にある見出しには追加の上余白を付けません。本文の外側ですでに取った余白と重複させないためです。見出しから直後の文章までは基本の `gap` を保ちます。スライド内の配置はスライドのレイアウトとして扱い、この表は適用しません。

### 画面幅が変わっても関係を保つ

既存の余白トークンは `clamp()` で変化します。ペアトークンだけでなく `--space-m` などの単独トークンも流動的です。ペアトークンは、小さい画面と大きい画面で異なる段階へ変化させたいときに使います。

横並びから縦並びへ変わったら、要素同士の関係をその軸で見直します。たとえば自己紹介の画像と文章は同じ話題なので、縦並びでは `--space-l-xl` でつなぎます。一方、異なる作品が縦に並ぶ場合は `--space-2xl` で項目を区切ります。

広い画面の数値を一律に半分にするのではなく、「まとまりの中より、まとまり同士が離れている」という関係を保ちます。大きな空白によってページが終わったように見える場合は、セクション間隔や前後の内容量を見直します。

### 実装とレビュー

- 繰り返し並ぶ要素の間隔は、親の `gap` で管理します。内容と枠の距離には `padding`、特定の関係だけに必要な追加距離には `margin` を使います。
- `gap`・`margin`・`padding` の合計が実際の要素間隔になります。個々の指定値だけでなく、描画された距離を確認します。文字の行間や画像内の空白も、見た目の距離に影響します。
- 元の値は `src/styles/global.css` を参照します。用途を表す変数が必要な場合は、そのページや部品の範囲で既存トークンから組み立てます。トップの `--home-section-gap` がその例です。
- 320px 程度の狭い画面、PC、並び方が変わる幅の前後で確認します。200% 拡大、長い見出し、複数行の説明でも、関連する情報が離れすぎず、重なりや横はみ出しがないか確認します。
- レビューでは「どの要素同士か」「どの関係を伝えたいか」「実際にどう見えるか」を記録します。数値が表と違うだけで不具合とは判断しません。確認していない表示条件は未検証とします。

### 方針の根拠

関係の近い要素を空間でまとめる考え方は、[better-layout の Grouping and alignment](https://github.com/jakubkrehel/skills/blob/main/skills/better-layout/grouping-and-alignment.md) を参照しています。同資料はグループ間を内部の2倍以上とするルールを提示していますが、このサイトでは差をつけるための出発点として扱い、機械的な合否基準にはしません。

144〜180px などの具体値は、このポートフォリオの情報量・既存トークン・表現意図に合わせた設計判断です。規格で定められた値でも、ユーザーテストで最適性が証明された値でもありません。外部の指針、サイト固有の判断、実画面での検証結果を区別して扱います。

## コンポーネントの構成

- `src/ui/` は見た目を担う純粋なコンポーネントです。
- `src/features/` は機能を担います。Container の `index.tsx` に状態・副作用、`presenter.tsx` に props を描画する処理を置きます。
- props は `export type <Name>Props` として公開します。
- スタイルは `index.module.css` に書き、インライン style は原則使いません。
- アイコンは `react-icons` の `Fi*` 系を使います。
- 関数引数はオブジェクト形式にします。DOM / React などが定めるイベントハンドラのシグネチャは例外です。

## よく使う表現

- 画像ズームは親に `overflow: hidden`、画像に `transform` の 0.3 秒の transition を設定し、hover 時に `scale(1.1)` にします。
- テキストの hover 色には `--color-link` を使います。
- ピル型は `--radius-infinity`、hover 背景は `--color-accent` を使います。
- 一覧リンクは `Button` に `href`、目的がわかる `aria-label`、`endIcon={FiArrowRight}` を渡して構成します。

## コンポーネントを選ぶ

`ui/` の Docs に各コンポーネントの用途・制約・プロパティ・実例をまとめています。`Tag` は既存の Storybook 資料も引き続き参照できます。

`Header`・`Footer`・`AnimationIcon` はサイト固有です。独自のナビゲーション・SNS リンク・アニメーション状態を持つため、汎用部品として使う際はその前提を確認します。Footer の画像は `public/` から Storybook に配信します。

## 確認方法

デザイン段階からコントラスト、ズーム耐性、キーボード操作、フォーカス、具体的な画像の代替テキストを確認します。WCAG 2.1 AA はこのサイトの設計目標であり、この資料の掲載自体が準拠検証の完了を意味するものではありません。

アニメーションは `html.stop` で停止でき、停止状態を `localStorage` に保存できることを確認します。

Storybook で実例・操作・アクセシビリティを確認し、意味のある動作は Vitest で検証します。props をそのまま表示するだけの自明なテストは追加しません。

# ライティングガイドライン

このポートフォリオにおける、フォント選定・文字組み・文章構成の基準。[デザイン原則](./design-principles.md) がビジュアルの「なぜ」を規定するのに対し、こちらは文字・文章という情報伝達面の「なぜ」を規定する。

## 結論 — 読みやすさは「書体」「レイアウト」「構成」の 3 つに分解できる

文章の読みやすさは単一の工夫では決まらず、次の 3 つの層が独立して積み上がっている。

1. **書体自体の読みやすさ**: フォントそのものの視認性・判読性
2. **文字のレイアウトの組み方**: 文字サイズ・行長・行間など、画面上の配置
3. **文章構成**: 見出しの階層構造や、論理展開の組み立て方

1・2 は WCAG の達成基準に基づく客観的な基準、3 は情報の伝わりやすさに関わる基準として、それぞれ判断基準を定める。

## 1. 書体自体の読みやすさ

### 基本書体

アクセシビリティへの配慮を優先し、視認性・判読性に優れた UD フォント（ユニバーサルデザインフォント）をベースにする。

- **判断基準**: 新しいフォントを検討するときは、まず UD フォント（UD 新ゴ等）の範囲で候補を探す

### 長文コンテンツでの切り替え（未実装）

UD フォントは一目で情報を認識する能力に長けるが、長文における可読性（読み続けやすさ）については必ずしも最適ではない。

- **Why**: 短文・UI ラベルは「速く正確に読める」ことが、長文は「読み続けられる」ことが重要で、最適なフォントの性質が異なる
- **判断基準**: ブログなど長文を読ませるページで可読性が課題になったら、記事本文のみ別フォントへの切り替えを検討する。UI 全体は巻き込まない

## 2. 文字のレイアウトの組み方（WCAG 準拠）

### 文字サイズ・テキストの拡大（達成基準 1.4.4 Resize text・レベル AA）

支援技術なしで 200% まで拡大しても、コンテンツや機能が失われない状態を維持する。

- **判断基準**: 文字サイズは `px` 固定せず相対単位（`rem` / `clamp()`）で指定し、16px 相当を下限にする

### 行長・行間（達成基準 1.4.8 Visual Presentation・レベル AAA）

1 行の文字数は全角 40 文字（半角 80 文字相当）以下、行間は行の高さの 1.5 倍以上とする。超えると視線移動がスムーズにいかず、読んでいる行を見失う原因になる。

このサイトは AA 準拠を基本方針としており AAA 達成基準への適合は必須ではないが、可読性向上のベストプラクティスとして本項目のみ採用する。

- **判断基準**: 本文の幅・行間は専用のデザイントークンを使う。文字数ベースの厳密な制御が必要になったら `ch` 単位への切り替えを検討する

## 3. 文章構成

### 見出しの階層構造（達成基準 1.3.1 Info and Relationships・レベル A）

見出し（h1〜h6）は文字の大小・強弱ではなく、文書の論理構造を表すために使う。レベルを飛ばさず、入れ子関係が意味のある階層になっていることを、スクリーンリーダー等の支援技術が機械的に判別できる状態を維持する。

- **判断基準**: 1 ページに h1 は 1 つ。それ以下は h2 → h3 → h4 とレベルを飛ばさず順に下げる。「文字を大きく/太くしたいだけ」の視覚的な強調目的で見出し要素を使わない

### 論理構成（ピラミッド構造）

『考える技術・書く技術』のピラミッド構造を基本とする。ブログ記事・README・PR の説明文など、まとまった文章を書くとき全般に適用する。

1. **結論の明示**: 最初に、最も主張したい内容（結論）を簡潔に書く
2. **根拠の提示**: 結論を支える根拠・説明を続ける
3. **並列性の確保**: 根拠を並べるときは、それらが同じレベルの理由になっているか揃える。接続詞の使い方が揃っているかを確認し、論理構造を明確にする

- **判断基準**: 文章を書き始める前に結論を一文で言えるか自問する。言えない場合は、結論が固まる前に書き始めている
